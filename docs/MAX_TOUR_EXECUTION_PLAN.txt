STAGE 6 — MAX TOUR BUSINESS SCHEMA

Next development block after Stage 5 code setup:

1. tours
2. tour_images
3. tour_dates
4. tour_prices
5. customers
6. bookings
7. booking_items
8. promocodes only if required

Design rules:
- dates/capacity belong to explicit tour departures;
- final prices are server-controlled;
- archived tours remain referentially safe for historic bookings;
- no hard delete for business objects referenced by orders;
- public catalog and admin mutations are separate APIs;
- booking engine is implemented after catalog/date/price model is stable.

PLANNED PUBLIC API

GET /api/v1/tours
GET /api/v1/tours/:id
GET /api/v1/tours/:id/dates

PLANNED ADMIN API

POST /api/v1/admin/tours
PATCH /api/v1/admin/tours/:id
POST /api/v1/admin/tours/:id/dates
PATCH /api/v1/admin/tour-dates/:id

All admin mutations require RBAC and audit logging.
