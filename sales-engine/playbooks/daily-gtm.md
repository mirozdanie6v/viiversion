# VIIVERSION Daily GTM Playbook v1.0

## Goal

The workday is a portfolio of revenue motions. Direct outreach is only one lane.

A healthy day balances:
1. immediate cashflow,
2. existing pipeline movement,
3. one repeatable-distribution milestone,
4. partner leverage,
5. at least one long-cycle or marketplace action when relevant.

## Default operating day

- FOLLOW_UP — 30m: replies and due follow-ups first.
- FAST_DIRECT — 60–75m: up to 20 qualified short offers.
- PLATFORM_DISTRIBUTION / PRODUCTIZATION — 90–120m: one closed app/plugin/platform milestone.
- PARTNER_B2B2B — 30–45m: partner/POS/agency actions.
- FREELANCE_MARKETPLACE or ENTERPRISE_VENDOR — 30–45m.
- PRODUCT_LAUNCH — 45–90m when a launch wave is active.

This is a template, not a rigid calendar. Customer replies, launch deadlines and high-value opportunities can override it.

## What “20 cold offers” means

It does not mean writing 20 large custom proposals.

FAST_DIRECT uses qualified leads, one concrete product, approved product/vertical templates, short product-first messaging and a relevant proof asset.

The target is up to 20 quality first touches inside one focused block.

If fewer than 20 Ready leads exist, send fewer. Spend remaining time qualifying the lead buffer; do not lower quality.

## Distribution work is sales work

Preparing a ChatGPT app submission, WordPress plugin package, Clover sandbox demo, Square integration proof, Product Hunt launch pack or Odoo adapter is commercial work when it removes an active distribution blocker.

Every such task must have product, ecosystem, milestone, owner, due date, blocker and definition of done.

That work belongs in Distribution_Pipeline, not in an untracked development bucket.

## Product × channel

Use Distribution_Matrix before allocating time.

- PRIMARY — main natural distribution channel.
- SECONDARY — useful additional channel.
- LATER — only after readiness/demand conditions are met.
- NO — do not spend GTM time now.

Examples:
- Proposal Studio → ChatGPT app directory + Product Hunt + global direct/partners.
- Website Audit Agent → WordPress.org + ChatGPT apps + agencies.
- PayBridge/POS middleware → POS integrators + Square/Clover/Odoo/Shopify ecosystems.
- Booking Engine → direct/partners now; platform distribution after generic product/API extraction.
- Telecom/Oracle/ETL → enterprise/vendor lane, not Product Hunt.

## Product Hunt

Product Hunt is a launch/discovery motion. It is useful for self-serve digital products with a live usable product and strong craft. It is not the billing system and it is not a substitute for ongoing distribution.

Track launch preparation and post-launch activation separately.

## Platform ecosystems

Treat each ecosystem as its own distribution project.

Typical stages:
1. feasibility,
2. developer account / sandbox,
3. generic product/API readiness,
4. platform adapter,
5. listing assets/legal/support,
6. submission,
7. review,
8. published,
9. installs/users,
10. monetization/retention.

Do not let marketplace approval block earlier merchant validation when platform rules allow seller-authorized/self-serve integrations.

## Daily_GTM

Each weekday the operating brief should create/update Daily_GTM with only the actions that matter today.

Each row must contain date, priority, motion, channel, product/focus, task, target, timebox, owner, source/pipeline, status and result.

A task is complete only when the output exists, not when time was spent.

## Weekly portfolio review

Review results by motion, not one blended metric.

Ask:
- Did FAST_DIRECT create cash or qualified conversations?
- Did FOLLOW_UP move stages?
- Did PARTNER create leverage/repeat pipeline?
- Did PLATFORM_DISTRIBUTION move a product closer to publication/installs?
- Did PRODUCT_LAUNCH create activation/feedback?
- Did FREELANCE create wins/reviews?
- Did ENTERPRISE create qualified high-ticket next steps?
- Did PRODUCTIZATION remove a real distribution blocker?

Then reallocate next week’s time accordingly.
